# 色分けの設計（画面用）

**色は情報を運ばない。色は、他の手がかりで既に運ばれている情報を、二重にするために使う。**

この原則は配慮ではなく仕様上の制約である。日本国内で色弱者は約320万人（男性の約20人に1人）、加齢による水晶体の黄変も加わる。学級の児童・保護者・教員のいずれかに該当者がいる前提で組む。

## 着手前に決めること

**いくつのものを区別するのか。** これが色数の上限を決め、上限が設計の可否を決める。

| 役割 | 上限 | 超えたときの手段 |
|---|---|---|
| 文字色 | **2色**（黒＋青） | 太さ・下線・囲み・記号 |
| 塗り（広い面・帯・セル背景） | **2色**（青系淡・黄系淡） | 3つ目は白（無地）に割り当てる |
| 線・アイコン・小面積の印 | **4色** | 形（●▲■◆）とラベルの併用 |
| グラフの系列 | **4色**＋直接ラベル | 線種・マーカー形・凡例を線の隣に置く |

上限は実測に基づく（`references/verify.md`）。**上限を超える設計は色以外の手がかりを追加するまで着手しない。** 色数を増やす方向で解決しようとした時点で設計が誤っている。

## 既定トークン

そのまま使える。値を変える場合は必ず検証スクリプトを通す。

```css
:root{
  /* 文字 */
  --ink:        #1A1A1A;  /* 本文 */
  --ink-sub:    #616870;  /* ラベル・補助 5.6:1 */
  --ink-link:   #0F5EA8;  /* リンク・強調 6.6:1 ＋下線必須 */
  --ink-alert:  #C0330A;  /* 注意・エラー 5.6:1 ＋記号と語必須 */
  /* 区別する印（線・アイコン・小面積、最大4） */
  --cat-1:      #0F5EA8;  /* 青 */
  --cat-2:      #C86A00;  /* 橙 */
  --cat-3:      #6E4310;  /* 茶 */
  --cat-4:      #7A7F86;  /* 灰 */
  /* 塗り（最大2、上に --ink を載せて可読） */
  --fill-a:     #D7E8F8;  /* 青系淡 */
  --fill-b:     #FBE3B4;  /* 黄系淡 */
  /* 面に白文字を載せる場合 */
  --solid-on:   #0F5EA8;  /* 白文字 6.6:1 */
  --solid-alert:#C0330A;  /* 白文字 5.6:1 */
}
```

`--cat-2`（#C86A00）と`--cat-4`（#7A7F86）は白地に対し3.8:1・4.0:1。**面や線には使えるが本文文字には使えない。** 文字に回すときは `--ink-sub` か #A85800 に置き換える。

## 使ってはいけない組み合わせ

実測ΔE00（強度2色覚シミュレーション、閾値18）。数値は `scripts/check-palette.mjs` の出力。

| 組み合わせ | 用例 | 最悪値 | 何が起きるか |
|---|---|---|---|
| 赤 × 緑 | ○×、提出済／未提出、正誤 | **8.6**（1型） | 同じ色になる。学校で最も頻出の失敗 |
| 青 × 緑 | 進行中／完了 | **6.2**（3型） | 同じ色になる |
| 赤 × 黒 | 強調文字と本文 | — | 1型では赤が暗く沈み、黒と混じる |
| 紺 × 紫、青 × 紫 | リンクと訪問済リンク | — | 一般色覚・高齢者ともに困難 |
| 黄緑 × 黄 | 強調マーカー | — | 明度も色相も近い |
| 淡色どうし3色以上 | 表の行の塗り分け | **6.7**（1型） | 淡色は色相が潰れる。塗りは2色まで |

**赤と緑を正誤に使わない。** 代わりに `--cat-1`＋「✓ できた」と `--ink-alert`＋「× もういちど」。色を取り去っても意味が残る。

## 二重符号化の型

色に必ず1つ以上を重ねる。どれを重ねるかは情報の性質で選ぶ。

- **記号**：✓ × ● ▲ ■ ◆（状態・カテゴリ）
- **語**：「できた」「まだ」（状態。児童向けでは記号より語が確実）
- **位置**：左＝前、右＝後（順序）
- **形・太さ**：枠線2px→4px（選択中）
- **下線**：リンク。色だけのリンクは不可
- **明度差**：色相が潰れても残る唯一の手がかり。同カテゴリ内の濃淡はこれで作る

「色を外したモノクロ画面で意味が通るか」を自問し、通らなければ設計を戻す。

## 検証

**色を確定する前に必ず実行する。目視と印象で決めない。**

```bash
node scripts/check-palette.mjs "#0F5EA8,#C86A00,#6E4310"            # 線・アイコン
node scripts/check-palette.mjs --role tint "#D7E8F8,#FBE3B4"        # 塗り
node scripts/check-palette.mjs --text "#0F5EA8" "#0F5EA8,#C86A00"   # 文字色も検査
```

1型・2型・3型の各シミュレーション下でのΔE00、明度比、背景コントラストを出し、不合格があれば終了コード1を返す。**不合格が出たら色を差し替える。既定トークンに戻すのが最短。** 判定の根拠と閾値の較正記録は `references/verify.md`。

### 検査に入れる色の範囲

**1回の検査に入れるのは「同じ判断の中で並ぶ色」だけ。** 画面上の色を全部まとめて渡すと、比べる必要のない組が不合格として出る（偽陽性）。

- 同じ検査に入れる … 凡例の系列どうし、タブどうし、状態表示どうし、図の中で意味を分けている色どうし
- 別の検査に分ける … 器の色（枠・見出し）と中身の色、必須マークと図の色、装飾の色

判断の指標は「**利用者がその2色を見比べて意味を取り違えることがあるか**」。取り違えようがない層どうしは、色が一致しても実害がない。ただし**分けた根拠は言葉にして残す**こと。面倒だから分けた、では偽陰性になる。

## 教室固有の条件

- **投影**：プロジェクタは淡色を白に飛ばす。投影する画面は塗りに頼らず、線・記号・明度差で組む
- **端末**：児童機はChromebook（CZ1104FM2A）。安価な液晶で視野角が浅く、斜めから見ると淡色が沈む。淡色どうしの区別を必要にしない
- **光環境**：窓際・屋外での使用がある。コントラスト比は最低値ではなく余裕をもって取る
- **教員機と私用機**：同じ画面を別環境で見る。特定ディスプレイでの見えを前提にしない

## frontend-design との併用

- **frontend-design が決める**：色の性格、パレットの雰囲気、タイポグラフィ、レイアウト、signature要素
- **このスキルが決める**：区別すべき情報に色を割り当てられるか、何色までか、色以外に何を重ねるか

衝突したときは**このスキルが勝つ**。ただし勝ち方は「地味な色に戻す」ではない。frontend-designが選んだ色相はできるだけ保ち、明度と彩度を動かして閾値に通す。通らない色相のときだけ、その色をカテゴリ識別から外して装飾に回す（背景・見出し・アクセントは自由に使える。**識別に使う色だけが制約を受ける**）。
