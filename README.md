# worksheet-platform

小学校向けのワークシート集約プラットフォーム。Google Apps Script で動く。

児童が書き込む定型ワークシートを教師が作り、**集約対象にした入力欄がそのままスプレッドシートの列になる**。全員分を1枚に並べて電子黒板に投影したり、印刷したりできる。

## 何のために作ったか

Google Workspace と Classroom が構造的に埋められない穴は3つ。

1. **35人分をまとめて紙にできない**（Classroom は提出物を一覧できるが一括印刷ができない）
2. **全員の同じ欄だけを抜き出して並べられない**（フォームにできない中核）
3. **日本語組版ができない**（縦書き・マス目・ルビ）

Google フォームは質問を縦一列に並べるので、**図と問いが同じ視野に入らない**。児童はスクロールして図を見て、戻って答える。ワークシートなら図の隣に答える欄がある。この差は低学年ほど大きい。

## このリポジトリの位置づけ

**動くコードの正本は Apps Script プロジェクト。ここは読み取り専用のミラー。**

直すときは Apps Script を先に直し、**動いたもの**をここへ上げる。逆をやると、動かないコードが履歴に残る。

`Store.gs` の `MASTER_ID` と `FOLDER_ID` は**空にしてある**。IDを書いたまま公開しないこと。児童の氏名やメールはコードに入っていないので、この2行を除けば公開しても個人情報の流出にはならない。

### サーバ（.gs）

| ファイル | 責務 |
|---|---|
| `Main.gs` | ルーティングのみ |
| `Store.gs` | マスター／単元ファイルへのアクセス、権限、名簿、キャッシュ |
| `Schema.gs` | テンプレートのスキーマ版・検証・移行 |
| `Lesson.gs` | テンプレート、回答、列同期 |
| `Admin.gs` | 単元・授業の作成／改名／削除／並べ替え／公開 |
| `Collect.gs` | 抽出集約（取り上げの指定と読み出し） |
| `Port.gs` | 書き出しと単元一括取り込み |
| `Test.gs` | 自動テスト（`runTests` を実行） |

| ファイル | 責務 |
|---|---|

| `registry` | **オブジェクト種別の定義。拡張はここだけ** |
| `layout` | 座標の自動配置と取り込みの正規化 |
| `render` | ページ描画、画面遷移、回答収集 |

| `import` | 取り込み専用（`?view=import`） |
| `collect` | 抽出集約（`?view=collect`） |

## データ構造

```
マスターファイル（1つ）   単元／授業／名簿／教師
単元ファイル（単元ごと）   _設定（テンプレート）＋ 授業ごとに1シート
```

**授業シートが回答の正本。**

| A 更新日時 | B メール | C 氏名 | D 取り上げ | E以降 入力欄（1行目がラベル） |
|---|---|---|---|---|

Forms の回答シートと同じ形。ただし回答は追加ではなく**上書き**で、児童が保存するたび同じ行が更新される。

D「取り上げ」は授業で見せる順番。教師が☆を押した順に 1, 2, 3… が入る。

## 触る前に知っておくこと

**種別の追加は `registry.html` の `KIND` に1つ足すだけ。** ツールバー、既定値、描画、設定画面、集約列、自動配置、取り込み案内がすべて追随する。ここを分散させないこと。

**サーバは種別を知らない。** 複数選択かどうかはエディタがテンプレートに `multi: true` を書き込み、サーバは `o.multi` を見るだけ。種別リストをサーバとクライアントで二重に持たない。

**GAS のウェブアプリはサンドボックス iframe で動く。** クライアント側の `location.search` にパラメータが入らず、`location` を書き換えても遷移しない。パラメータはテンプレート経由で渡し、遷移は `navTo`（`_top`）で行う。普通の Web アプリと同じ書き方にすると画面遷移が全く動かない。

**排他制御はない。** 公開時に名簿全員分の行を作るため、保存で行の追加が起きない。児童は自分の行だけを1回の書き込みで更新するので、35人が同時でも競合しない。

**列が変わってもデータは消えない。** テンプレート保存時に列を作り直すが、既存データはラベルで突き合わせて引き継ぐ。削除した入力欄の列は `(削除)ラベル` として残す。

## 開発の規約

**改修したら `runTests` を実行する。** 31件。組版、列同期、型復元、スキーマ移行を検査する。スプレッドシートには触らないので、実行してもデータは変わらない。

**設計の判断基準は「使用時の認知的負荷 ＞ 機能性 ＞ 実装の容易さ」。** 実装が複雑になっても、使うときのややこしさを削るほうを選ぶ。とくに**利用者に手順を覚えさせる設計は採らない**。「あとで更新ボタンを押す」ような仕組みは、押し忘れを前提にしている時点で失敗している。

## 制約

- Classroom API は使わない（環境で使用不可）。名簿は貼り付け、成績は Classroom 側で手入力
- GAS は HTML を PDF に変換できない。出力はブラウザの印刷のみ
- テンプレートは `_設定` の1セル。上限50,000字、40,000字で警告
- 児童は画像を配置できない。写真提出は Classroom に任せる
- 手書き描画は非対応
- 複数選択の選択肢にカンマは使えない（シート上でカンマ区切りに保存するため。エディタが自動で取り除く）
